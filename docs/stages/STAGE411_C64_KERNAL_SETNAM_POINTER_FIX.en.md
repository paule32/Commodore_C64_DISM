# Stage 411 – Fix the KERNAL SETNAM Pointer

**Basis:** `d64_dism_asm_410.zip`.

## Cause of continuing LOAD ERROR 4

The Stage-410 PETSCII filename conversion was correct. However, the internal MOS6510 assembler interprets `#>label+1` as `high(label)+1`, **not** `high(label+1)`. In the generated PRG, `SPRITES.SPR` was stored at `$0CD5`, but `LDX #$D5; LDY #$0D` passed `$0DD5` to KERNAL `SETNAM` (`$FFBD`)—one whole memory page too high. This can produce graphical garbage in filenames and KERNAL LOAD error 4.

## Fix

Compiler-generated low/high immediate expressions with an offset are now unambiguously parenthesized:

```asm
    LDX #<(name+1)
    LDY #>(name+1)
```

The correction applies wherever the compiler builds affected pointers, while keeping byte order and existing assembly syntax intact. Tests examine generated bytes, labels, and KERNAL pointer values rather than assuming that a source-level change alone ensures correct output.

## Limitations

A genuinely mounted and correctly configured VICE drive is still required. The fix addresses a reproducible pointer bug; other possible host-drive failures are separate.

## Source code and command examples (unchanged)

```asm
    LDX #<(name+1)
    LDY #>(name+1)
    JSR $FFBD
```
