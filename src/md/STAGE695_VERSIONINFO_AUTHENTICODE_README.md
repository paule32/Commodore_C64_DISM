# Stage 695 — Versionsinformationen und Authenticode
Basis: Stage 694. Linker-Baum für PE32 und PE32+: Manifest, Versionsinformationen, Authenticode (bisher Signierung). SignTool-Pfad mit Ordner-Icon links, Auto-Suche. Explizit ungültiger Pfad führt zum Fehler statt stiller Ersatzsuche.

VERSIONINFO: optional, standardmäßig aus. CompanyName, FileDescription, FileVersion, ProductName, ProductVersion, LegalCopyright, LegalTrademarks, OriginalFilename, InternalName, Comments. Versionsnummern müssen vier Komponenten 0–65535 enthalten. Leere Dateinamen werden aus dem Ziel abgeleitet. RT_VERSION ID 1, Sprache 0409, Unicode 1200. Bestehende gleichnamige Ressource derselben Sprache wird ersetzt. Einbettung in fünf vorhandenen Signier-Buildpfaden, vor der Signatur. Bei den beiden direkten COFF-Linkerpfaden erfolgt die Ressourceneinbettung nach der internen Kompaktierung; in den drei anderen vor der finalen Kompaktierung.

Projektsektionen Settings.Windows.32Bit.Linker.VersionInfo bzw. 64Bit, JSON Data. Signierung bleibt rückwärtskompatibel in Linker.Signierung. Änderungen markieren das Projekt, Speichern/Speichern unter persistieren. Publisher wird per Zertifikatprüfung oder nach Signierung ausgelesen, nicht als frei editierbarer vertrauenswürdiger Name. PFX-Passwort nur im Sitzungsspeicher; SignTool erhält es wie bisher als Prozessargument. Windows PowerShell für die Zertifikatauslese erforderlich. Die tatsächliche Windows-Vertrauensprüfung erfolgt über SignTool verify /pa /v, falls aktiviert. Keine Umgehung von UAC.

Tests: 30 erfolgreich (Stage 693, 694, 695). Binärpayload, Versionen, JSON und statische Verdrahtung. Kein nativer Windows/PyQt5-Laufzeit- oder Signierungstest in der Linux-Umgebung. Python-Syntax mit temporär entfernten lazy-Markern geprüft; Originalmarker bleiben erhalten.
